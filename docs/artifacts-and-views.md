# Artifacts and views (api 1)

This file covers figures and interaction: the artifact a tool returns and what the app stores, the line the model reads, how the fallback SVG is sanitized and displayed, the renderer, theming, the interactive view (how it is loaded, its Content Security Policy, asset inlining, the `postMessage` protocol), `state` summaries, and answer mode with `grade`. It documents host API version 1 as implemented by the app build of 2026-11-15. Luau examples were run through `plugin test`. Sanitizer examples were run through the app's `sanitize_svg` function compiled on its own. Everything that needs a running app (storage, the UI, the iframe) is taken from the app's source (`crates/harness/src/artifacts.rs`, `agent.rs`, `plugins/mod.rs`, `crates/app/src/lib.rs`, `ui/artifacts.js`, `ui/viewhost.js`) and was not exercised in a running app; those parts are marked "from source". The return shape and its errors are in [package.md](package.md#a-tool-with-artifact--true), the SVG builders in [host-api.md](host-api.md#harnesssvg).

## The artifact contract

A tool declared with `artifact = true` returns:

```lua
return {
  text = "2 bars; the total is 9.",
  artifact = {
    kind = "svg",
    svg = figure,        -- complete SVG document, a string
    data = data,         -- optional table
  },
}
```

| Field | Purpose |
|---|---|
| `text` | What the model reads about the result. Optional; at most 16 KiB |
| `artifact.kind` | `"svg"`, the only kind |
| `artifact.svg` | The static figure, called the fallback. It is what is shown when there is no view, when the plugin is removed or disabled, on a device the plugin does not support, and in replays |
| `artifact.data` | Any JSON-convertible table, at most 256 KiB as JSON. Stored with the artifact and given to the view. `nil` is stored as `null` and reaches the view as `{}` |

`data` should hold everything needed to redraw or interact with the figure, and nothing the learner must not see ([hidden answers](#hidden-answers)). If `data.title` is a string, the UI uses it as the accessible label of a figure the model did not place itself.

### What the app stores (from source)

After a successful return the app sanitizes `artifact.svg` and appends an `artifact` op to the session:

```json
{
  "op": "artifact", "opId": "01J…", "at": "2026-11-15T10:00:00.000Z",
  "artifactId": "01J…",
  "pluginId": "tally", "pluginVersion": "0.1.0",
  "packageHash": "<sha256 over the package's files>",
  "tool": "tally_show",
  "input": { "items": [ { "label": "Cats", "count": 3 } ] },
  "data": { "items": [ { "label": "Cats", "count": 3 } ], "total": 3 },
  "fallbackSvg": "<svg …>",
  "platforms": ["desktop", "mobile"]
}
```

- `artifactId` is generated by the app; the plugin never sees it at tool time. The view receives it in `init`.
- `input` is the tool call's arguments as the model sent them.
- `fallbackSvg` is the sanitized `artifact.svg`. Replay never runs a plugin again: the stored figure and data are all that is used later.

### What the model reads (from source)

The tool result is `text`, a blank line (omitted when `text` is empty), and the placement line:

```text
2 bars; the total is 9.

artifact: 01J… — place it once with ![a short description](artifact:01J…) next to the sentence that refers to it
```

The model places the figure with Markdown image syntax, `![alt](artifact:<id>)`; the alt text becomes the figure's accessible name. An artifact made during a turn but not placed is appended after that turn's message. An unknown id is shown as the alt text in brackets.

### How the fallback is displayed (from source)

The UI sanitizes the stored SVG again (DOMPurify's SVG profile plus the rules below), inserts it into a `<figure>`, removes the root element's `width` and `height` attributes and sets `max-width: 100%; height: auto`, `role="img"` and `aria-label` = the alt text. The figure therefore scales to the column width using the root `viewBox`. `svg.document` sets one; a root written by hand must have a `viewBox` or it will not scale.

## The sanitizer

`artifact.svg` is parsed as XML and rewritten before it is stored. A failure makes the tool call an error; the model reads `<tool name> refused: <message>`.

| Message | When |
|---|---|
| `the fallback SVG is <n> KiB (limit 256 KiB); ask for a simpler figure` | Longer than 262 144 bytes |
| `the SVG is not well-formed XML (<parser message>)` | Mismatched or unclosed tags, a raw `<` or `&` in text |
| `the fallback is not an SVG document` | The output contains no `<svg` |
| `the SVG is not UTF-8` | Not valid UTF-8 after rewriting |

Removed:

| What | Rule |
|---|---|
| Elements, with everything inside them | `script`, `foreignObject`, `iframe`, `object`, `embed`, `audio`, `video`, `animate`, `animateTransform`, `animateMotion`, `set`, `discard`, `style`. Matched on the local name, case-insensitively, so `svg:script` is removed too |
| Attributes by name | Names starting with `on` (any case), and `style` |
| `href`, `xlink:href` | Kept only when the value starts with `#`, or with `data:image/png;base64,`, `data:image/jpeg;base64,`, `data:image/gif;base64,` or `data:image/webp;base64,`. Otherwise the attribute is removed and the element stays |
| Any attribute by value | Removed when the value (entity-decoded, lower-cased) contains `javascript:`, a backslash, `image-set(`, `image(`, `src(`, `cross-fade(`, `element(`, or a `url(` that is not followed by `#` |
| Document parts | Comments, CDATA sections, the XML declaration, processing instructions, the doctype |
| Entities | `&lt; &gt; &amp; &quot; &apos;` and numeric references are decoded and written back escaped. Any other entity (`&nbsp;`) is dropped |
| A repeated attribute on one element | The first occurrence is kept |

Kept: every other element and attribute, including `defs`, `marker`, `linearGradient`, `filter`, `clipPath`, `mask`, `use`, `image`, `a`, `polygon`, `polyline`, `ellipse`, `tspan`, and `class`, `id`, `transform`, `marker-end="url(#id)"`, `fill="url(#id)"`. Attribute values are re-escaped and always written with double quotes.

Observed input and output:

```text
IN : <svg><rect style="fill:red" fill="blue"/><style>rect{fill:red}</style><script>alert(1)</script><foreignObject><div>hi</div></foreignObject></svg>
OUT: <svg><rect fill="blue"/></svg>

IN : <svg><rect fill="url(https://x/y)" stroke="red" onclick="x()" ONLOAD="y()"/><animate attributeName="x"/><set/></svg>
OUT: <svg><rect stroke="red"/></svg>

IN : <svg><use href="#arrow"/><image href="https://example.com/a.png"/><image href="data:image/png;base64,AAAA"/><image href="data:image/svg+xml;base64,AAAA"/><a href="https://example.com">link</a></svg>
OUT: <svg><use href="#arrow"/><image/><image href="data:image/png;base64,AAAA"/><image/><a>link</a></svg>

IN : <svg><defs><marker id="arrow" markerWidth="6" markerHeight="6" refX="5" refY="3" orient="auto"><path d="M0 0L6 3L0 6z" fill="currentColor"/></marker></defs><line x1="0" y1="0" x2="10" y2="0" marker-end="url(#arrow)"/><polygon points="0,0 10,0 5,8.66"/><text><tspan>x</tspan></text></svg>
OUT: (unchanged)

IN : <svg><text x="1" y="2">a &lt; b &amp; "c" &gt; 'd' &nbsp; &#937;</text></svg>
OUT: <svg><text x="1" y="2">a &lt; b &amp; "c" &gt; 'd'  Ω</text></svg>

IN : <svg xmlns="http://www.w3.org/2000/svg"><rect x="9" x="1" y="2" width="30" height="40"/></svg>
OUT: <svg xmlns="http://www.w3.org/2000/svg"><rect x="9" y="2" width="30" height="40"/></svg>

IN : <svg><g>a<b&c</g></svg>
ERR: the SVG is not well-formed XML (ill-formed document: expected `</b&c</g>`, but `</svg>` was found)

IN : <svg><g>unclosed</svg>
ERR: the SVG is not well-formed XML (ill-formed document: expected `</g>`, but `</svg>` was found)

IN : <div>no</div>
ERR: the fallback is not an SVG document
```

Notes:

- The sanitizer does not check that the figure is meaningful SVG: `<circle cx="NaN" cy="inf" r="-inf"/>` and an attribute named `1` pass unchanged. It also does not require `<svg` to be the root; text around it is kept.
- What the `@harness/svg` builders refuse (`on…` attributes, external `href`) is narrower than what the sanitizer removes. Markup written by hand gets no error for a removed element or attribute; it is silently gone from the stored figure.
- The UI applies the same element, attribute, link and `url(` rules a second time when it inserts the figure.

## The renderer

`[[renderer]].entry` names an exported function that takes an artifact's stored `data` (converted from JSON) and returns the SVG string:

```lua
local function render(data: Data): string
  return draw(data)
end
```

The manifest requires a renderer for every plugin with an artifact tool. In the app build examined here nothing in the host calls it: the stored `fallbackSvg` is always the `artifact.svg` the tool returned, and the function that would run the renderer (`LuauPlugin::render`) has no caller in the app's source. If it is called, a non-string result is the error `renderer returned <value>, not an SVG string` (from source), and the 2 000 ms limit applies.

Write it anyway, as the single drawing function of the plugin:

- the tool calls it to produce `artifact.svg` from the `data` it is about to store, so the figure and the data cannot disagree;
- a view can list it in `calls` and ask for a redraw with changed data;
- a test can assert `render(out.artifact.data) == out.artifact.svg`, which proves `data` is sufficient to redraw.

Remember that the argument has been through JSON: an empty list arrives as an empty table, holes and `nil` fields are gone, and every table that was not a pure `1..n` list is an object with string keys.

## Theming

The figure is inserted into the app's page and must read in the light and the dark theme.

- Use `currentColor` for strokes and fills. `svg.document` sets `stroke="currentColor"` and `fill="none"` on the root.
- Vary emphasis with `fill-opacity`, `stroke-opacity`, `stroke-width`, `stroke-dasharray`, `font-weight`, not with fixed colours. A fixed colour that works on white may vanish on a dark background.
- Text needs `fill="currentColor"` and `stroke="none"`, or it is drawn as outlines.
- A `style` attribute and a `<style>` element are removed. Use presentation attributes (`fill`, `stroke`, `font-size`, `text-anchor`, …). `class` is kept but there is no stylesheet to give it meaning in the fallback.
- Fonts: the figure inherits the page font. Do not rely on a specific font's metrics for layout; leave slack around text.

## Views

A view is one HTML document that shows the artifact interactively. It is optional. Without a view, or where the view cannot run, the fallback is shown.

```toml
[[view]]
name = "Dial"
html = "views/dial.html"
calls = ["scale"]
answer = true
```

### When the view is shown (from source)

The UI shows the fallback first and replaces it with the view when the plugin that made the artifact is installed, enabled, has a view, and lists this device's platform. In every other case the fallback stays: a replay on a device without the plugin, a removed or disabled plugin, a platform the plugin does not list, or a failure to load.

### How the document is loaded (from source)

- The UI creates `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer">`, initially 320 px high, with the alt text as its title. There is no `allow-same-origin`: the frame has an opaque origin and cannot reach the app's page, its storage, or the app's command bridge.
- The frame's URL is a dedicated scheme served by the app (`pluginview://localhost/<id>`; `http://pluginview.localhost/<id>` on Windows and Android). The response carries this header:

  ```text
  Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; font-src data:; connect-src 'none'; base-uri 'none'; form-action 'none'
  ```

  and `Cache-Control: no-store`. The HTML is read from the package each time a view is opened.

What the policy means for the view:

| Allowed | Not allowed |
|---|---|
| Inline `<script>` and inline event handlers | Scripts loaded by URL; `eval` and `new Function` (the policy has no `'unsafe-eval'`) |
| Inline `<style>` and `style` attributes | Stylesheets loaded by URL |
| Images and fonts as `data:` URIs | Images, fonts, media from any URL |
| `postMessage` to the parent | `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, form submission, navigation, pop-ups, `localStorage`, cookies |

### Asset inlining (from source)

Because nothing can be loaded by URL, the app inlines package files into the document before serving it:

| In the HTML | Becomes |
|---|---|
| `<link … href="views/dial.css">` | `<style>…file contents…</style>` |
| `<script src="views/dial.js"></script>` | `<script>…file contents…</script>` |

- `href` and `src` are resolved **from the package root**, not from the HTML file's folder: write `views/dial.js`, not `dial.js`. A leading `./` is accepted.
- The file must be inside the package (after resolving `..` and symlinks) and readable as UTF-8 text. Otherwise the tag is left as written and the policy blocks it, so the asset is missing without an error.
- Every `<link>` with a readable `href` is turned into `<style>`, whatever its `rel`. Other attributes of the replaced tag (`type="module"`, `defer`, `media`) are dropped.
- The file contents are inserted as they are. A script containing the text `</script>` ends the element early.
- The matching is textual, not an HTML parser: write the tags in the plain forms above, with the closing `</script>` present.
- Nothing else is inlined. Put images in the document as `data:` URIs or draw them as inline SVG.

### The message protocol (from source: `ui/viewhost.js`, protocol 1)

The view and the app exchange objects with `postMessage`. Every message has `protocol: 1`. The app ignores a message that does not come from that iframe, is not an object, or has another `protocol`. The view should ignore messages whose `event.source` is not `parent`.

| Direction | Message | Meaning |
|---|---|---|
| app → view | `{ protocol: 1, type: "init", artifact: { artifactId, data }, theme, answer }` | Sent once, on the iframe's `load` event. `data` is the stored `artifact.data` (`{}` when the tool stored none). `theme` is described below. `answer` is `true` only when the view is the answer surface of a pending question |
| app → view | `{ protocol: 1, type: "theme", theme }` | The theme changed while the view was open |
| view → app | `{ protocol: 1, type: "call", id, fn, args }` | Call an exported Luau function. `id` is a number or string chosen by the view, `fn` a string; a message with other types is ignored without an answer. `args` is passed as the function's single argument (`null`/absent → `nil`) |
| app → view | `{ protocol: 1, type: "result", id, ok: true, value }` | The function's return value as JSON |
| app → view | `{ protocol: 1, type: "result", id, ok: false, error }` | The call failed; `error` is a string |
| view → app | `{ protocol: 1, type: "resize", height }` | Set the iframe height in px |
| view → app | `{ protocol: 1, type: "state", summary }` | A short summary of what the learner changed |
| view → app | `{ protocol: 1, type: "submit", answer }` | Answer mode: the learner's answer |

**`call`.**

- `fn` must be listed in `[[view]].calls`. Otherwise the UI answers `` `<fn>` is not available to this view`` without running anything; the core checks again (`` `<fn>` is not one of the view's callable functions``).
- One call per frame at a time. A `call` sent while another is pending is answered immediately with `ok: false, error: "busy"`. Wait for each `result` before sending the next call; do not queue calls on a slider's every `input` event.
- Each call has 200 ms, including loading the entry module if the VM is new. Beyond it the error is `plugin time limit (200 ms) exceeded`. Any error discards the VM, so module-level state is lost; the function should depend only on its argument.
- Other errors: the Lua error text; `` plugin `<id>` is disabled; enable it in Settings → Plugins``.
- The return value converts by the usual [Lua → JSON rules](package.md#lua--json): an empty table arrives as `{}`, never `[]`.

**`resize`.** `height` is converted to a number, rounded, and clamped between 160 px and 80 % of the window height. A non-finite value is ignored. The frame does not resize itself: send `resize` after each change of layout.

**`state`.** See [State summaries](#state-summaries).

**`submit`.** Ignored unless `init` had `answer: true`. After a `submit` the frame is inert: the app drops its `call`, `state` and `submit` messages and still honours `resize`. If sending the answer fails, the frame becomes live again and the UI shows `Couldn’t send the answer: <reason>`; on success it shows `Answer submitted.`

**`theme`.** An object mapping token names to CSS values taken from the app's stylesheet: `paper`, `raised`, `ink`, `ink-2`, `ink-3`, `rule`, `rule-strong`, `accent`, `accent-hover`, `on-accent`, `danger`, `select`, `font-ui`. Set them as custom properties and use them in the view's CSS (`color: var(--ink)`, `background: var(--paper)`), so the view matches light and dark.

### A minimal view

`views/dial.html`, with `calls = ["scale"]`. The script was run against a stand-in for the app side that sends and answers the messages above; it was not run in the app's webview.

```html
<!doctype html>
<html>
<head>
<meta charset="utf-8">
<style>
  body { margin: 0; padding: 12px; font: 14px var(--font-ui, sans-serif); color: var(--ink, #111); background: var(--paper, #fff); }
  button { color: var(--on-accent, #fff); background: var(--accent, #36c); border: 0; padding: 6px 12px; }
</style>
</head>
<body>
<label>Factor <input id="factor" type="range" min="0.5" max="2" step="0.1" value="1"></label>
<p id="shown"></p>
<button id="submit" hidden>Submit</button>
<script>
(() => {
  const pending = new Map();
  let nextId = 1;
  let busy = false;
  const send = (m) => parent.postMessage({ protocol: 1, ...m }, '*');

  // One call at a time: the host answers a second one with the error "busy".
  const call = (fn, args) => new Promise((resolve, reject) => {
    const id = nextId++;
    pending.set(id, { resolve, reject });
    send({ type: 'call', id, fn, args });
  });

  const theme = (tokens) => {
    for (const [name, value] of Object.entries(tokens || {})) {
      document.documentElement.style.setProperty('--' + name, value);
    }
  };
  const resize = () => send({ type: 'resize', height: document.documentElement.scrollHeight });

  const factor = document.getElementById('factor');
  const shown = document.getElementById('shown');
  const submit = document.getElementById('submit');

  async function update(tellHost) {
    if (busy) return;
    busy = true;
    try {
      const out = await call('scale', { factor: Number(factor.value) });
      shown.textContent = `width ${out.width}`;
      if (tellHost) send({ type: 'state', summary: `factor ${factor.value}, width ${out.width}` });
    } catch (err) {
      shown.textContent = String(err.message || err);
    } finally {
      busy = false;
      resize();
    }
  }

  window.addEventListener('message', (event) => {
    const m = event.data;
    if (event.source !== parent || !m || typeof m !== 'object' || m.protocol !== 1) return;
    if (m.type === 'init') {
      theme(m.theme);
      if (typeof m.artifact.data.factor === 'number') factor.value = String(m.artifact.data.factor);
      submit.hidden = !m.answer;
      update(false);          // draw, but post no `state` on load
    } else if (m.type === 'theme') {
      theme(m.theme);
    } else if (m.type === 'result') {
      const p = pending.get(m.id);
      if (!p) return;
      pending.delete(m.id);
      if (m.ok) p.resolve(m.value); else p.reject(new Error(m.error));
    }
  });

  factor.addEventListener('change', () => update(true));
  submit.addEventListener('click', () => send({ type: 'submit', answer: { value: Number(factor.value) } }));
})();
</script>
</body>
</html>
```

The Luau side, in `src/main.luau`:

```lua
-- A view call: listed in [[view]].calls, called with the view's `args`.
local function scale(args)
  assert(type(args) == "table" and type(args.factor) == "number", "factor must be a number")
  return { width = math.round(100 * args.factor) }
end
```

`scale({ factor = 1.5 })` returns `{"width":150}` to the view; `scale({})` fails with `src/main.luau:3: factor must be a number`, which arrives as `ok: false`.

Messages this view sent for: `init` with `data = { factor: 1.5 }` and `answer: true`, the learner moving the slider to 2, then pressing Submit:

```json
[{"protocol":1,"type":"call","id":1,"fn":"scale","args":{"factor":1.5}},
 {"protocol":1,"type":"resize","height":123},
 {"protocol":1,"type":"call","id":2,"fn":"scale","args":{"factor":2}},
 {"protocol":1,"type":"state","summary":"factor 2, width 200"},
 {"protocol":1,"type":"resize","height":123},
 {"protocol":1,"type":"submit","answer":{"value":2}}]
```

Guidance for views:

- Use the `change` event or a debounce, not every `input` event, for anything that makes a `call`.
- Do not animate on load; honour `prefers-reduced-motion`.
- Validate `m.artifact.data` before use: it is whatever the tool stored, after the JSON conversion.
- Much interaction needs no `call` at all. Compute in JavaScript from `data` when that is enough; use a `call` when the logic already exists in Luau and must agree with the tool.

## State summaries

`state` lets the tutor know what the learner did in a view without logging every movement.

```js
send({ type: 'state', summary: 'R2 = 2.2 kΩ, Vout = 3.4 V' });
```

The path of a summary (from source):

1. The UI ignores a `summary` that is not a string or is blank, cuts it to 500 characters, and forwards at most one per 250 ms per view (the latest wins).
2. The core refuses it if the artifact is not in the session (`unknown artifact <id>`), replaces control characters and line breaks with spaces, cuts to 500 characters, trims, and keeps only the latest summary per artifact in memory.
3. When the learner sends their next message, each held summary is stored as a `viewState` op just before it.
4. In the request to the model, the summaries are appended to that learner message after a blank line, one line per artifact, sorted by artifact id:

   ```text
   [view state 01J…] R2 = 2.2 kΩ, Vout = 3.4 V
   ```

The learner's own message is stored and displayed without these lines. Summaries with no learner message after them (the app quit first) are lost.

Rules for a view:

- Send `state` only after the learner changed something, never on load. Otherwise opening a session logs a line for every figure on screen.
- One line, in plain words, with the values that matter for teaching. It is prompt text for the tutor, not a data format.
- Never include an answer the learner must not see reflected back, and nothing private.

## Answer mode

With `answer = true`, the tutor can ask a question that the learner answers in the view.

### The question (from source)

The tutor calls the core tool `question_ask` with a `view` object:

```json
{
  "role": "check", "nodeId": "divider-rule", "format": "free",
  "prompt": "Set the factor so that the bar is 150 wide.",
  "answer": "factor 1.5",
  "view": {
    "artifactId": "01J…",
    "task": "Move the slider, then press Submit.",
    "target": { "equals": 1.5, "tolerance": 0.05 }
  }
}
```

| `view` field | Rule |
|---|---|
| `artifactId` | String; an artifact of this session |
| `task` | Non-empty string; shown to the learner above the view |
| `target` | Object; its content is the plugin's own design. It is committed in the tool call and given to `grade` |

The call is refused (`question_ask refused: <message>`) with one of:

- `` `view` must be an object``, `view.artifactId is required`, `view.task is required`, `view.target must be an object`;
- ``no artifact `<id>` in this session``;
- ``the plugin that made `<id>` isn't installed``;
- ``the plugin that made `<id>` is disabled; ask without the view``;
- ``the plugin that made `<id>` doesn't run on this device; ask without the view``;
- ``the plugin that made `<id>` isn't active in this section; ask without the view``;
- `that artifact's view can't be an answer surface` (the view lacks `answer = true`).

The tutor learns how to build `target` from the plugin: describe it in the tool `description`, in the tool's result `text`, or in the prompt fragment. A tool can return the exact `target` to copy in its `text`.

### Submitting and grading (from source)

1. The UI shows the prompt, the `task`, and the view with `init.answer == true`.
2. The view posts `{ type: "submit", answer }`. `answer` may be any JSON value.
3. The core calls the plugin's exported `grade(answer, target)`: `answer` is the submitted value, `target` the object from the question, both converted from JSON. The time limit is 2 000 ms.
4. The tutor receives, as the result of its `question_ask` call:

   ```json
   { "questionId": "…", "artifactId": "01J…", "answer": { "value": 1.5 }, "view": { "correct": true, "detail": "submitted 1.5, target 1.5 ± 0.05" } }
   ```

   `view` is whatever `grade` returned, converted to JSON and passed through unchanged.
5. The tutor records the verdict with its own tool. The plugin never records a verdict and never talks to the learner.

If `grade` raises an error, or the plugin is missing or disabled at that moment, the answer is not accepted, the question stays open and the view becomes live again. The UI shows `Couldn’t send the answer: the plugin couldn't grade the answer: <error>`; for a disabled plugin the reason is `the plugin that made this view is disabled; enable it in Settings → Plugins to submit this answer`.

### The `grade` contract

```lua
-- `answer` is what the view submitted, `target` what the tutor committed.
local function grade(answer, target)
  if type(answer) ~= "table" or type(answer.value) ~= "number" then
    return { correct = false, detail = "nothing numeric was submitted" }
  end
  local tolerance = target.tolerance or 0
  local correct = math.abs(answer.value - target.equals) <= tolerance
  return {
    correct = correct,
    detail = string.format("submitted %g, target %g ± %g", answer.value, target.equals, tolerance),
  }
end
```

Observed results:

```text
grade({ value = 3.04 }, { equals = 3, tolerance = 0.05 })  --> {"correct":true,"detail":"submitted 3.04, target 3 ± 0.05"}
grade({ value = 3.2 },  { equals = 3, tolerance = 0.05 })  --> {"correct":false,"detail":"submitted 3.2, target 3 ± 0.05"}
grade(nil, { equals = 3 })                                  --> {"correct":false,"detail":"nothing numeric was submitted"}
```

- Return `{ correct = <boolean>, detail = "<one line for the tutor>" }`. The host does not enforce the shape, but the tutor is told to expect it. More fields are allowed.
- `answer` comes from the view, which is untrusted input: it can be `nil`, a string, or a table of any shape. Return `correct = false` with a reason rather than raising, unless the submission cannot be graded at all.
- `target` was written by the model: validate it too, and raise a clear error when it is unusable, so the question stays open instead of being graded wrongly.
- `grade` must be a pure function of its two arguments. It runs in the shared VM, possibly a fresh one, and has no access to the artifact, its `data`, or the tool input.
- `detail` may name the target value. Only the tutor reads it.

### Who sees what (from source)

| | Learner | View (iframe) | Tutor (model) | Plugin Luau code |
|---|---|---|---|---|
| Tool input | no | no | yes (it wrote it) | yes, in the tool |
| Tool `text` | no (unless the tutor quotes it) | no | yes | yes |
| Fallback SVG | yes | no | no | yes |
| `artifact.data` | whatever the view shows; all of it is readable inside the frame | yes, all of it | no | yes, in the tool; the renderer or a view call only if passed in |
| `state` summary | no | it wrote it | yes, with the next learner message | no |
| `view.task` | yes | no | yes | no |
| `view.target` | not displayed; not sent to the view | no | yes | yes, in `grade` |
| `submit` answer | as a line "Answer submitted in the figure." (or the answer itself if it is a string) | it wrote it | yes | yes, in `grade` |
| `grade` result | no | no | yes | it wrote it |

### Hidden answers

- **Never put an answer in `artifact.data` or in the SVG.** The view receives all of `data`, a script in the frame can read all of it, and the fallback SVG is displayed as it is. Hidden text in the SVG (zero opacity, off-canvas) is still in the document.
- The answer key belongs in the tool's `text` (the model reads it and can copy it into `view.target`) and nowhere else. If a tool hides parts of a figure for the learner to fill in, remove those parts from `data` as well, and test that they are absent from both `artifact.svg` and `artifact.data`.
- `target` is the only channel from the tutor to `grade`. The view never receives it, so the view cannot check the answer itself and cannot leak it.
- A view must not reveal correctness on its own. It only submits. Feedback comes from the tutor.
- `state` summaries go to the tutor, not to the learner, but treat them as visible: they are stored in the session.
